# Semantic verbal fluency and left inferior parietal cortical thickness

This project follows Track C of the statistics course. It uses clinical and cognitive data from the Uniform Data Set (UDS) and MRI measurements from a teaching subset of the National Alzheimer's Coordinating Center (NACC) dataset. The primary analysis asks how left inferior parietal cortical thickness relates to performance on a 60-second animal-naming task among participants classified as cognitively normal. The research question, variables, and analysis plan are described in the [project card](PROJECT_CARD.md).

## Reproduce the Phase 1 analysis

Run the following from the project root with Python 3.10 or later. The packages in `requirements.txt` support figure generation and notebook execution.

```shell
python3 -m pip install -r requirements.txt
python3 -m src.data_audit > reports/phase1/data_audit.json
python3 -m src.build_dataset
python3 -m src.descriptive_statistics
python3 -m src.phase1_figures
```

The [data audit](reports/phase1/data_audit.json) maps the source columns, counts unique IDs, and records why selected values could not be used. It contains aggregate counts only.

`src.build_dataset` creates the local table `data/processed/participants.csv` and the [sample flow report](reports/phase1/sample_flow.json). The table has one row per matched participant. The build reads the original input files without modifying them.

- Columns such as `ANIMALS` and `EDUC` contain usable values. A blank there means a usable value is unavailable. The `_RAW` columns retain the supplied values, and the `_ISSUE` columns record why an entry was unusable.
- Sample flags use `1` for inclusion and `0` for exclusion. `eligible_model_normal` identifies the primary modeling sample and `eligible_model_all` identifies the supplementary sample. The [project card](PROJECT_CARD.md) gives the criteria and denominators for each.

`src.descriptive_statistics` produces the [descriptive results](reports/phase1/descriptive_statistics.json). These include variable-specific denominators, sex and cognitive status frequencies, empirical distributions for animal-naming scores and years of education, and comparisons across cognitive status groups. The script checks that the participant table matches the sample flow. The output contains aggregate statistics.

`src.phase1_figures` creates four grayscale vector graphics ready to include in LaTeX under `figures/phase1/`. The [project card](PROJECT_CARD.md) describes what each figure shows and which participants it includes.

## Build the LaTeX report

After running the analysis, generate the shared tables and compile the report from the project root. Tectonic uses the XeTeX engine and may need an internet connection on its first run to retrieve LaTeX packages and fonts.

```shell
python3 -m src.phase1_tables
tectonic -Z search-path="$PWD" --outdir reports reports/phase1/phase1.tex
```

To rerun the notebook and save the cell outputs, use the Python environment where the project requirements are installed.

```shell
python3 -m jupyter execute --inplace --timeout=90 notebooks/phase1.ipynb
```

### Reproduce Phase 3

Start with the course CSVs and a Python environment containing the packages in `requirements.txt`, then run the commands below from the project root. The first two rebuild the local participant table and the reference for the fixed Phase 2 cutoff. The rest reproduce the planned Phase 3 analyses, run the review and generate the shared numeric macros. The LaTeX report uses the existing template. On its first build, Tectonic may need to download standard packages and fonts.

```shell
python3 -m src.build_dataset
python3 -m src.phase2_event_probabilities
python3 -m src.phase3_plan
python3 -m src.phase3_mean_intervals
python3 -m src.phase3_sampling
python3 -m src.phase3_mri_contrast
python3 -m src.phase3_contrast_bootstrap
python3 -m src.phase3_group_comparison
python3 -m src.phase3_review
python3 -m src.phase3_tables
tectonic -Z search-path="$PWD" --outdir reports reports/phase3/phase3.tex
```

Run the notebook with the kernel from that same Python environment. It recalculates the estimates, both bootstraps and the tests, compares them with the shared results, and runs the integrated review again.

```shell
python3 -m jupyter execute --inplace --timeout=180 notebooks/phase3.ipynb
```

The report gets its numbers from `reports/phase3/tables.tex`, which `src.phase3_tables` generates. The table generator requires current inputs and an up-to-date review. That review rebuilds the participant table in memory, reproduces the numerical results and all five vector figures, and records source hashes and environment versions. Its 11 checks establish computational consistency; the report discusses the sampling, preparation and small-group limitations separately.

Use `reports/phase3/hypothesis_tests.json` for the final adjustment and decisions for both tests. The Step 4 and 5 JSON files keep the pending fields recorded at those earlier stages. Section 10 of the report shows where all nine general and five Track C requirements are addressed. The local Phase 3 deliverables are ready for review. The student handles Git publication, the `phase-3` tag and CW packaging manually.
